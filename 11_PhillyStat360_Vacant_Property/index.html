Case Study 01

Finding the vacant homes the city hasn't found yet

Philadelphia's official vacancy list is a record of enforcement, not a record of vacancy. This model scores every residential parcel in the city on how likely it is to be vacant, so inspectors can be sent by evidence rather than by complaint.

The problem is the label, not the model

Philadelphia already publishes a vacancy list. The trouble is how a property gets on it. A parcel enters the record when it generates enforcement activity, which means the list is a good description of where the city has already looked and a poor description of where vacancy actually is.

Three kinds of property fall straight through that gap. Absentee owners who keep the taxes current and the complaints quiet. Properties where utilities are still billed and paid, so the usual vacancy signal never fires. And blocks where neighbours do not file complaints, which are frequently the blocks with the least capacity to chase the city for a response.

That last one matters. If the input to a targeting system is complaint volume, the system inherits whoever is best at complaining. The point of building a model here was to find the properties the complaint channel never surfaces.

Assembling a picture from six systems

No single city dataset says whether a house is empty, but a lot of them say something adjacent. The feature set pulls 34 predictors from six municipal systems, with a five-year lookback window on utility, permit, and complaint history so the model sees trajectory rather than a single snapshot.

  • Licenses and Inspections violations, which carry the enforcement history
  • Real estate transfers, which show whether a property is still moving through the market
  • OPA property records, for physical and assessment characteristics
  • Clean and seal actions, the city's direct intervention on open properties
  • Business licenses, which distinguish an active commercial use from a dormant one
  • Spatial lag measures, which let a parcel borrow evidence from its neighbours

The spatial lag features do real work. Vacancy clusters, so the condition of the parcels around a property is genuinely informative about the property itself. It also creates the main methodological trap in the project, which is covered below.

Choosing a model that can be trusted, not just one that scores well

Four base learners were trained and compared: logistic regression, random forest, XGBoost, and LightGBM. The gradient boosted models are the ones that usually win a leaderboard, and on raw discrimination they were competitive.

The final model is a 50/50 blend of a calibrated logistic regression and a random forest. That choice trades a small amount of headline performance for two things the city needs more.

Calibration over ranking

A ranking model tells you which parcel is more suspicious than another. A calibrated model tells you that a parcel scored 0.8 is vacant about eighty percent of the time. Those are different products. An inspection team planning a week of work needs the second one, because it lets them reason about how many doors they will knock on for nothing. Uncalibrated boosted trees are confidently wrong at the extremes, which is exactly where a targeting list gets used.

An interpretable half

Keeping logistic regression in the blend means half the model can be explained in a sentence to someone who has to defend the list in public. When a property owner asks why their house was flagged, "the model said so" is not an answer a city can give.

Why the cross-validation is grouped by geography

This is the part of the project most likely to have gone quietly wrong, and the part I would defend hardest.

With spatial lag features in the model, a random train and test split leaks. A parcel in the test set has neighbours in the training set, and those neighbours are literally an input to its prediction. The model gets to see the answer through the back door. Validation scores come back beautiful and the model falls apart the moment it is asked about a neighbourhood it has not memorised.

Validation is therefore grouped by ZIP code and by census tract, so whole geographies are held out at a time. The model is scored on its ability to generalise to places it has never seen, which is the only thing that matters if the city intends to run it citywide across 521 tracts. The reported AUC of 0.940 is under that harder test, not under a random split.

The equity audit

A vacancy model is not a neutral instrument. It is a device for deciding where the city sends people with clipboards and enforcement authority, and those visits have consequences for the people living nearby.

Before the scores went anywhere, flag rates were audited across poverty quintiles. The question was straightforward. Does the model concentrate attention on low-income neighbourhoods by more than the underlying vacancy actually justifies?

This check exists because the failure mode is invisible without it. A model trained on enforcement history will happily reproduce the geography of past enforcement and report excellent accuracy while doing so. Accuracy against a biased label is not evidence of fairness. The only way to know is to look at the flag distribution directly and be willing to change the model if the answer is bad.

Where a targeting tool sends inspectors is a policy question. Treating it as a technical detail is how analytically sound projects end up doing harm.

What it is actually for

The output is not a verdict. It is a prioritised list with a probability attached, which turns a reactive complaint queue into something a team can plan against. The city can direct structural inspections at the properties most likely to need them. Housing organisations, courts, and planners get a calibrated starting point rather than an anecdote.

The scores are published through a public dashboard so the reasoning is inspectable rather than locked in a model file.

Limits, and what I would do differently

The honest constraint on this project is the ground truth. The model is trained against the city's own vacancy determinations, which is the same enforcement-shaped record the project set out to improve on. It learns to find properties that look like the ones the city has already caught. That is genuinely useful and it is not the same as finding every vacant house.

Three things I would push on with more time.

  • Validate against an independent source rather than the enforcement record. A field-verified sample, even a small stratified one, would give a much better read on whether the model finds anything the existing process would have missed.
  • Report the equity audit as a standing output rather than a pre-deployment gate. Flag rates by quintile should ship next to the AUC every time the model is retrained, because drift in that number matters more than drift in accuracy.
  • Attach a confidence band to each score. A single probability invites false precision, and inspection teams would be better served by knowing which predictions the model is unsure about.
